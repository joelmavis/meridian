# Meridian

Meridian 是面向欧洲科技与 AI 研究者的情报雷达，重点服务欧洲 AI 治理及其对外影响研究。它不是新闻聚合器；它从大量动态中固定筛出三条值得继续研究的信号，说明变化对欧盟规则、欧洲能力、国际规范扩散和技术主权意味着什么。

## 它解决什么问题

研究者每天会遇到大量政策公告、公司发布、媒体报道和社交平台讨论。真正困难的不是“找到更多信息”，而是判断：哪些事件发生了实质变化、是否有可靠原始来源、是否值得占用下一小时的研究时间。

Meridian 将这个判断过程固定为一套可复用的流程：按事件去重、识别变化、回到一手来源、保留反向信号，再把结果收束成可执行的下一步。

## 安装

Meridian 遵循通用 Agent Skill 目录结构，仓库根目录中的 `SKILL.md` 是调用入口。克隆仓库后，将整个目录放进所用 Agent 的 Skills 目录即可。

### Codex

```bash
git clone https://github.com/joelmavis/meridian.git ~/.codex/skills/meridian
```

重新打开 Codex 会话后，可直接输入：

```text
使用 $meridian 生成截至北京时间今天 07:00 的每日情报雷达。
```

### Claude Code

```bash
git clone https://github.com/joelmavis/meridian.git ~/.claude/skills/meridian
```

重新启动 Claude Code 或开启新会话后，使用 `/meridian`，也可以在任务中明确要求调用 Meridian。

### 其他 AI Agent

如果 Agent 支持包含 YAML frontmatter 的 `SKILL.md`，将本仓库复制到其 Skills 目录即可。Agent 还需要具备联网检索与网页读取能力，才能执行实时雷达；Meridian 本身不提供搜索 API、付费媒体权限或自动定时器。

## 快速使用

Meridian 默认输出中文 Markdown。日报固定三条信号；周报固定整理五条重要信号、共同变化、研究问题和内容候选。你可以在请求里改变时区、时间窗口或输出语言，但证据优先级、去重规则和研究边界不应被放宽。

## 适合谁使用

- 跟踪欧盟 AI Act、治理机构与政策实施的研究者和学生
- 研究欧盟规则国际影响、规范扩散、Brussels Effect 与全球南方回应的分析者
- 研究欧洲 AI 主权、算力、云与产业能力，或企业如何回应欧盟监管的团队
- 希望把日常信息收集转化为研究问题或内容选题的独立研究者

它也适合已有明确主题但不想被新闻流淹没的人。它不适合需要实时预警、全网舆情监测或自动发布内容的场景。

## 监控范围

Meridian 以 **European AI Governance** 为核心，以 **The External Influence of EU AI Governance** 为研究特色。保留五条输出标签，但每条入选信号都必须说明与欧盟 AI 治理、欧洲 AI 能力或欧盟规则对外影响的关系：

1. 欧洲科技政治：数字政策、技术主权、战略自主、产业政策与科技安全。
2. AI 治理与 AI 主权：监管、安全、模型治理、标准，以及算力、数据和云主权。
3. 中美欧科技关系：作为欧盟规则、能力和外部竞争环境的比较视角。
4. 企业 AI 治理：重点观察企业如何回应欧盟监管与跨境合规。
5. 全球 AI 地缘政治与多边治理：重点观察欧盟治理规范在其他地区的采纳、改造、抵制和本土化。

美国、中国、全球南方和多边组织不是平行的泛 AI 新闻线。普通芯片、云、产品和融资消息，也只有在能够解释欧洲 AI 治理、技术主权或国际影响时才纳入。

## 如何使用

### 每日扫描

```text
使用 $meridian 扫描截至北京时间 07:00 的过去 24 小时内，欧盟 AI Act、European AI Office 和欧洲 AI 能力相关动态。
请以 Markdown 生成每日情报雷达：固定三条，说明每条与欧洲 AI 治理的关系，优先提供一手来源。
```

### 围绕具体问题扫描

```text
使用 $meridian 查看本周欧盟 AI 治理规则在其他国家或企业中的采纳、调整与抵制。
请输出周度情报雷达，并主动保留不支持“Brussels Effect”的反向信号。
```

### 追踪企业治理变化

```text
使用 $meridian 关注过去一周企业如何回应 AI Act 的市场准入与跨境合规要求。
只保留有公开文件、原始数据或可靠研究支持的变化。
```

## 它如何工作

1. 每日先查欧盟一手来源及 Reuters、FT、POLITICO Europe，再按当天线索触发其他来源；每周补充专业媒体、学术、视频与研究者动态。
2. 按“事件”而非“报道篇数”去重；同一政策被多家媒体转载仍只算一个信号。
3. 先通过欧洲 AI 治理主线筛选，再判断它是否带来政策、标准、战略、依赖关系、基础设施、企业实践或研究理解上的变化。
4. 将媒体、播客和社交平台作为发现入口，并尽量补充原始文件。
5. 固定输出三条：优先输出 P1 与最有价值的 P2；如不足三条，以相关、可靠的 P3 补足，并清楚标明其背景性质。
6. 为每个核心信号给出一个明确动作：忽略、保存、快速研究、专题研究或内容选题。

## 输出与价值

每日报告使用 Markdown，在开头标明报告基准时间与扫描范围，并固定输出三条信号。每条固定说明“发生了什么”“为什么重要”“所属研究方向”“来源”和“建议动作”；报告结尾另列“本日判断”，严格区分可确认事实与基于事实的推论。周报则把五个重要信号进一步整理为共同变化、可继续研究的问题和内容候选。

每日默认覆盖报告基准时间前的 24 小时。工作日晨报在周一会回看周末至报告时点，以免遗漏非工作日发生的重要变化。每条至少保留一个可访问链接；政策、数据和法规状态优先回到一手来源。

这种结构带来三点便利：减少重复阅读同一事件的转述；将“热度”与“研究价值”分开；让每条信息都有可追溯来源和下一步，而不是停留在收藏夹里。

## 来源与判断边界

正式取证顺序为：官方原始资料、学术文献与原始数据、专业研究报告、权威媒体、社交媒体观点。国际组织文件按其性质归层；企业公告仅证明其披露或承诺。社交平台与播客可以帮助发现议题，但不能单独证明重要事实；重要结论应回到可访问的原始文件。完整的 [来源注册表、优先域名、每日／每周组合与查询路由](sources/source-list.md) 说明了如何选源。

Meridian 会主动保留政策退坡、成员国分歧、项目失败、企业抵制或技术依赖加深等反向信号。它可以提出“这可能意味着”，但不替任何用户形成最终判断，也不宣布长期趋势已经成立。
